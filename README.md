# Mini-RAG pipeline — Deriv tech test

A replayable mini-RAG over a small product knowledge base. The pipeline
ingests `kb/*.txt`, chunks deterministically, retrieves with a hybrid
BM25 + dense-embedding index, generates citation-strict answers via a
local LLM (Ollama), and evaluates retrieval against ground truth.

The pipeline is **rebuildable from a clean checkout** — every artifact
under `artifacts/` is regenerated by `python main.py`.

---

## Quick start

```bash
# 1. Python 3.10–3.12 recommended (PyO3 still needs <3.14)
python3.12 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

# 2. (Optional but recommended) Start Ollama and pull a model:
#    The default is llama3:latest. Override with OLLAMA_MODEL.
ollama pull llama3

# 3. Run the full pipeline (default: paragraph chunking + LLM answers)
python main.py

# 4. Run both chunking strategies and write the comparison
python main.py --compare-chunking

# 5. Skip the LLM entirely (deterministic extractive answers)
python main.py --no-llm

# 6. Validate all generated artifacts
python validate.py

# 7. (Stretch) Run the local API
uvicorn api:app --reload --port 8000
curl -X POST http://localhost:8000/answer \
     -H "content-type: application/json" \
     -d '{"question":"Can I withdraw demo profit?"}'
```

Or simply: `make install && make run && make validate`.

## Architecture

```
INIT
 → DOCUMENTS_LOADED       (load kb/*.txt, parse Title:/Section:)
 → DOCUMENTS_CHUNKED      (paragraph OR fixed-size strategy)
 → INDEX_BUILT            (BM25 + MiniLM dense embeddings, optional)
 → RETRIEVAL_COMPLETE     (top-3 per query, written to retrieval.json)
 → ANSWERS_GENERATED      (LLM via Ollama, citation-validated; extractive fallback)
 → EVALUATION_COMPLETE    (per-query hit/partial_hit/miss + aggregate)
 → VALIDATION_COMPLETE    (grounding check on every answer)
 → RESULTS_FINALISED
```

The state machine in `src/pipeline.py` rejects illegal transitions, so
answers cannot be generated before retrieval completes.

### Key design choices

- **Hybrid retrieval** (`src/retriever.py`): BM25 catches exact-match
  questions like "30 minutes" while dense embeddings catch paraphrases.
  Scores are min-max normalised and combined with `alpha=0.5`. Dense
  embeddings degrade gracefully to BM25-only if
  `sentence-transformers` is unavailable, so the pipeline still runs.
- **Citation-strict generation** (`src/answerer.py`): the LLM is forced
  to JSON output. Every citation it produces is re-validated **in code**
  against the retrieved chunks for that query — uncited or hallucinated
  references are stripped and the answer downgraded to
  `insufficient_context`. If JSON parsing fails or all citations are
  invalid, we fall back to a deterministic extractive answer (best
  sentence from top-1 chunk by content-token overlap).
- **No vector DB**: 4 documents × ~5 paragraphs each = ~20 chunks. A
  vector DB would be overkill for this scale; we use a numpy matmul over
  L2-normalised embeddings for cosine similarity.
- **Deterministic evaluation**: hit/partial_hit/miss are computed in
  code from `expected_doc_titles` ∩ top-3 — no LLM involved in scoring.

### Controlled vocabularies (`src/vocab.py`)

| Field | Allowed values |
|---|---|
| `answer_label` | `grounded_answer`, `insufficient_context`, `conflicting_context` |
| `retrieval_status` | `hit`, `partial_hit`, `miss` |
| Citation format | `[doc_title §chunk_id]` |


## Configuration

| Env var | Default | Purpose |
|---|---|---|
| `OLLAMA_URL` | `http://localhost:11434` | Ollama server endpoint |
| `OLLAMA_MODEL` | `llama3:latest` | Any local model (e.g. `qwen2.5:1.5b`, `mistral`) |
| `LLM_LOG_PATH` | `llm_calls.jsonl` | LLM call audit log path |

The pipeline runs **without** an LLM via `--no-llm`. The extractive
fallback picks the sentence in the top-1 chunk with the highest content-token
overlap against the question, and citation format is preserved.

---

## What the evaluator can do

- Replace `kb/*.txt` with other articles using the same `Title:` /
  `Section:` schema — the chunker will pick them up.
- Replace `queries.json` with other queries — the retriever, answerer,
  and evaluator are all generic over the queries file.
- Delete `artifacts/` and `llm_calls.jsonl` — `python main.py` will
  regenerate everything from `kb/` and `queries.json`.

The pipeline does **not** depend on exact filenames or document order.
Static precomputed outputs are not used.
